This files describes API changes in /report/studentsummary/*,
information provided here is intended especially for developers.

=== 0.5.3 ===
* New db/hooks.php registers \report_studentsummary\local\hook_callbacks::before_footer_html_generation(), which adds a
  Settings link to this plugin's row on the Plugins overview page (core gives report plugins none). Purge caches.

=== 0.5.2 ===
* The summary and box templates take two new context values, namelevel and boxlevel (heading levels 2..6).
  report_page::export_for_template() sets them to 2 and 3; course_report_page sets 3 and 4 because the page title is
  an h2. A caller that renders report_studentsummary/summary or /box itself must supply them.

=== 0.5.1 ===
* No API changes.

=== 0.5.0 ===
* The report pages accept a courseids[] request parameter (index.php and course.php). It only narrows
  \report_studentsummary\local\access::get_courses(); courses the viewer may not see stay excluded.
* New \report_studentsummary\form\filter_form::courseids_url_params() puts the choice into a URL as
  courseids[0], courseids[1], ... (Moodle 4.5's moodle_url refuses array values).
* Site-level time is left out of a summary when courses are chosen.

=== 0.4.6 ===
* New report_studentsummary_settings_link() in lib.php returns the "Plugin settings" link shown to users with
  moodle/site:config at the top of index.php and course.php.

=== 0.4.5 ===
* On Moodle 5.3+ the course page toolbar is a React component (js/esm/src/Toolbar.tsx, mounted with
  html_writer::react_component). course_report_page::react_toolbar() falls back to the Bootstrap toolbar when
  \core\output\react_component_renderable or js/esm/build/Toolbar.js is missing.
* amd/src/course.js talks to the component with document events.
